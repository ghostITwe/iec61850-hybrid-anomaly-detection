# Протокол эксперимента v1 (сетевая модальность)

Версия протокола фиксируется коммитом до просмотра тестовых метрик. Любое отклонение — в разделе «Журнал отклонений».

## 1. Вопрос и гипотезы
**Вопрос.** Даёт ли параллельное объединение оценок аномальности Autoencoder (AE) и Isolation Forest (IF) выигрыш по сравнению с каждым методом отдельно при сопоставимой доле ложных тревог?
**H0:** гибрид не лучше лучшего из одиночных методов по AP на общем тесте. **H1:** гибрид лучше. Отрицательный результат (H0) — полноценный результат.
Задача — **обнаружение отклонений**, а не определение причины: КЗ и кибератака обе могут быть аномалиями.

## 2. Данные
TU Delft CPPS dataset, **версия 2 (2026-10-19)**; DOI статьи 10.1109/ACCESS.2026.3699153. Версия, пути и sha256 — в `reports/inventory.csv`.
Используются сетевые захваты `.pcapng` (SV, GOOSE, фоновый трафик) и покадровые метки `*_labels.csv` (есть только для атак по сети).
Физические CSV RTDS в v1 для обучения не используются (меток нет, синхронизация с pcap не доказана — README §4).

## 3. Группы прогонов
| Группа | Сценарии | Роль |
|---|---|---|
| normal_pool | Baseline (5 прогонов) | единственная «норма»: train / val / test_normal по прогонам (3/1/1, seed в конфиге) |
| attack | GOOSE Injection, Reconnaissance, SV Injection | только тест, метки кадров |
| physical_fault | Fault (с/без повторного включения) | КЗ без сетевой атаки: только доля срабатываний |
| host_stress | Resource Exhaustion | хостовая атака без размеченных пакетов: только доля срабатываний |

Resource Exhaustion **не** используется как норма: README §6 относит его к атакам.

## 4. Окна, признаки, метки
Окна 1 с, шаг 0,5 с (`config/experiment_v1.yaml`). Признаки (`src/iecad/windows.py`): счётчики/байты по классам трафика, тайминг SV (мкс), разрывы и дубли `smpCnt`, изменения `stNum`/`sqNum` (только разности), доля кадров с 802.1Q. Набор `protocol_content` добавляет RMS токов/напряжений из SV (отдельный вариант, не основной).
**Запрещены:** MAC/IP (анонимизированы, идентифицируют атакующего), сырые `stNum`/`sqNum` (значения 773 и 10 названы в README как атакующие), любые метки.
Метка окна = 1, если в нём ≥1 злонамеренный кадр. Метки реплеев SV в README §6 получены по тайминговой фазе — тайминговые признаки частично воспроизводят логику разметки (ограничение, см. §9).

## 5. Предобработка
`sign·log1p|x|` → стандартизация (mean/std **только по train**, пол σ = 0,01) → clip ±10. Реализация: `src/iecad/prep.py`.

## 6. Модели
IF: 300 деревьев, `max_samples=auto`, seed. AE: MLP d→64→32→8→32→64→d, GELU, AdamW, MSE, ранняя остановка по val-норме. Оценка AE = MSE реконструкции окна. В обучении участвуют только train-окна нормы. Гиперпараметры **не подбираются по тесту**.

## 7. Гибрид (правило зафиксировано заранее)
Для каждого метода — эмпирическая CDF val-оценок (`rank_with_tail`: выше максимума val шкала продолжается логарифмом), гибрид = среднее двух рангов. Веса не оптимизируются.

## 8. Порог и метрики
Порог метода = 0,99-квантиль оценок val-нормы.
**Основная метрика — macro-AP:** AP считается отдельно внутри каждого семейства атак (GOOSE Injection, Reconnaissance, SV Injection; негативы — окна с меткой 0 тех же прогонов), затем усредняется по трём семействам. Причина: число положительных окон в семействах несопоставимо (GOOSE — 9–73 вредоносных кадра на прогон, SV — 144 000 кадров, разведка — тысячи), поэтому общий AP определялся бы почти целиком SV и разведкой.
Вторичные метрики: общий AP на объединённом тесте (test_normal + attack), ROC-AUC, Precision, Recall, F1, FPR, матрица ошибок; метрики по семействам, сценариям и ракурсам (vIED / attacker). Для групп physical_fault и host_stress — только доля срабатываний. FPR на чистом тестовом прогоне Baseline (alert_rates_no_attack.csv, split=test_normal) отчитывается отдельно от FPR на окнах с меткой 0 внутри атакующих прогонов.
Неопределённость: кластерный bootstrap по прогонам (500 повторов; для macro-AP ресэмплирование внутри семейства), разности гибрид − IF и гибрид − AE.
Утверждение «гибрид эффективнее» допустимо только если 95 % интервал разности macro-AP относительно **обоих** одиночных методов лежит выше нуля и FPR сопоставим.

## 9. Ограничения (заранее известные)
1. Норма — всего 5 прогонов: в val один прогон, порог по 0,99-квантилю нестабилен; тест_normal — один прогон. Результаты по FPR — оценки с большой неопределённостью.
2. Сдвиг сессий: по eda_network.csv число GOOSE-кадров за 60 с в безатакующих прогонах различается между сериями (Baseline — 220, baseline_priority_a — 249–250, Fault — 281–350), т.е. конфигурация стенда и фон меняются между сериями независимо от атак. Срабатывания на окнах с меткой 0 в атакующих прогонах — ложные тревоги по определению датасета, но частично отражают этот сдвиг, а не дефект метода; поэтому основная AP считается внутри семейства (негативы из тех же сессий), а FPR на чистом Baseline отчитывается отдельно.
2a. Потолочный эффект: инъекция SV удваивает поток (≈9600 кадров/с) и ломает монотонность `smpCnt`, поэтому ожидается AP≈1 у всех методов; различия методов ожидаются в GOOSE-инъекциях (малый след) и разведке.
3. Метки SV-реплеев производны от тайминга; детектор по тайминговым признакам частично подтверждает алгоритм разметки.
4. Физический канал и синхронизация pcap↔RTDS не исследуются в v1.
5. Обнаружение ≠ атрибуция причины (КЗ / атака / стресс хоста).
